## Planner's calls

1. **Two files outside the design's list.** The content security policy needs `next/vite.config.ts`. SvelteKit adds a hash for its own inline start-up script only through its `csp` option, which lives in the `sveltekit()` plugin call (mechanism 1). The repo has no `svelte.config.*`, and a header set from `+layout.server.ts` or a hook can't carry that hash, so it would block the page's script or allow every inline script, and acceptance item 3 forbids the second. A1 foresaw this: its plan's task 1 says "A3's plan must add" `next/vite.config.ts` "for the old app's CSP" (A1 plan line 88). The page checks need a committed home, and `next/tests/` belongs to A4. They go in `next/scripts/page-checks.mjs`, beside A1's `check-mutations.sh`. No pass in the round names either file (A4 and A5 list `next/src/routes/`, `next/src/lib/components/`, `next/cli/`, and `next/tests/`; A6 lists `scripts/` and `approval-queue/`). 2. **The policy.** `csp: { mode: 'hash', directives: { 'default-src': ['self'], 'script-src': ['self'], 'style-src': ['self', 'unsafe-inline'], 'img-src': ['self', 'data:'], 'object-src': ['none'], 'base-uri': ['self'], 'form-action': ['self'] } }`. The probe's header carried a `sha256-` hash in `script-src` and none in `style-src`, and the page still hydrated (mechanisms 1 and 2). `style-src` keeps `'unsafe-inline'` because the components set `style` attributes, which the item doesn't govern. If the built header ever shows a hash in `style-src`, browsers ignore `'unsafe-inline'` there, so page check 1 reads the header and fails on one. If hash mode stops the page hydrating in the real app, try `mode: 'nonce'`, then `'auto'`, with a `[mechanism]` line, before any stop.
3. **Remote images never load.** The policy blocks a remote image, but Chromium still raises a request event for it before the block (mechanism 4), and acceptance item 3 asks for no outside request. `next/src/lib/components/typeset.ts` therefore removes the `src` attribute of every `<img>` whose address isn't a path on the queue or a `data:` address, and keeps its `alt`. The policy stays as the second guard.
4. **Curly quotes.** The document library escapes `"` as `&quot;` and `'` as `&#39;` in text and code alike (mechanism 8), and `next/src/lib/doc/` is outside the list. `typeset.ts` exports a pure function over an HTML string that changes quotes only in text outside tags and outside `<code>`, `<pre>`, `<kbd>`, and `<samp>`. It handles both the raw and escaped forms. A double quote opens (“) at the start of a text run or after a space or one of `([{-` and closes (”) elsewhere. A single quote between two letters, or after a letter or digit, is an apostrophe (’); otherwise it opens (‘) or closes (’) by the same rule. The page's server load runs it over the title, every `html` segment, every option, both button sentences, and each merged sentence. Plain-text titles in the rail and rows go through the same function.
5. **Which tool sent a document.** The store's `Meta` holds no repo (mechanism 11). A document with pull requests takes its tool from the first one's repo.
