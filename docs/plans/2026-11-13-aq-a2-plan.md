## Planner's calls

1. **The hand-off is a record the command writes.** The store's records for a document, read in number order, fold into one state: waiting, decided, handed, or withdrawn. A `withdraw` record counts only while waiting. An `undo` record returns decided to waiting. A `handed` record names the decision it hands, `{action: "handed", at, decision: <n>}` with `n` the number of that decision's file, and turns decided into handed only when `n` is the number of the current decision. Any other action is a decision and counts only while waiting. Withdrawn and handed are final: every later record counts for nothing. Once the decision of a decided document is 20 seconds old by its `at`, `send` or `collect` writes the `handed` record through `writeDecision`, reads the records again, and prints the decision only if the fold now says handed. An Undo that took the lower number wins, the hand-off is void, and the wait goes on. A stale hand-off, one naming a decision that was undone and decided again, is void too, so the new decision waits its own 20 seconds. The fold is a pure function in `next/cli/state.ts`. Its doc comment tells A4 three things: the server imports this function and never writes its own fold; after writing an Undo or a decision, the server reads and folds again and tells Geoff the Undo or decision lost when the fold says handed or withdrawn; and only the command writes `handed` and `withdraw`, so the server refuses either from the page. The design's "Undo works until that hand-off" (line 151) rests on this order, and `writeDecision` numbers each record with `linkSync` so two writers never share a number (mechanism 1).
2. **Output.** `send` and `collect` print one JSON line on stdout, `{"id": <id>, ...the decision record}`, so a `collect` after a killed `send` prints the same line. Exit 0 for any decision. A withdrawn document exits 1 with `approval-queue: <id> was withdrawn` on stderr.
3. **`send` checks first.** It runs the same checks as `check` and prints the same lines. A fault exits 1 and stores nothing. A pending check also exits 1 and stores nothing, with `approval-queue: a check is still running; send it when the checks finish` on stderr (the design: "`send` refuses a pending check"). `check.ts` returns its pending lines apart so `send` can tell. Then `createDocument(root, source, {kind, title})` stores it, with `title` the parsed plain-text title.
4. **`send` on a report** prints the id alone on stdout and exits 0. Any other kind prints `approval-queue: stored <id>; waiting for a decision` on stderr at once, so a session that loses the command can still run `collect <id>`, then waits. The wait reads the store once a second, as the old wait loop does (old command lines 1101 to 1124). `send` never starts the server and never opens a browser.
5. **`collect <id>`** waits as `send` does. A report exits 1 with `approval-queue: <id> is a report; nothing to collect`. A malformed id exits 2 with the usage, and a well-formed id with no document exits 1 naming it.
6. **A malformed record.** When `readDecisions` throws `unreadable`, `send`, `collect`, and `withdraw` print `approval-queue: ` and the error's message, which names the file, and exit 1. Nothing reads it as "no decision" (backlog #49).
7. **`withdraw <id>`** folds the records first. A document already withdrawn exits 0 with `approval-queue: <id> was already withdrawn`, and a decided or handed one refuses as below, each writing nothing. A waiting one gets `{action: "withdraw", at}` through `writeDecision`, and the command reads and folds again, since a decision can land between the two reads. Withdrawn: it prints `approval-queue: withdrew <id>` on stderr and exits 0. Decided or handed: the withdraw came after a decision, so it prints the decision's JSON line on stdout, `approval-queue: <id> was decided before the withdraw; run collect <id>` on stderr, and exits 2. When the fold says decided rather than handed, stderr adds a second line, `approval-queue: the decision can still be undone; collect waits for the hand-off`. The withdrawal is a decision record with `action: "withdraw"`, the convention A1's plan set (A1 plan line 160).
8. **`land` ports the old checks.** In order: the ref matches `^[^/#\s]+/[^/#\s]+#[0-9]+$` and the sentence is not blank, else usage and exit 2. A stored `merge` document whose fold says waiting or decided (a decision not yet handed over can still be undone) and whose parsed `prs` hold the ref refuses with exit 2 naming it. A document or decision file that can't be read also refuses with exit 2 naming it, since the command can't then show the ref isn't waiting. Then `gh repo view <repo> --json defaultBranchRef` and `gh pr view <n> --repo <repo> --json state,isDraft,headRefOid,body,baseRefName,statusCheckRollup`. A base that isn't the default branch, a `## Before merge` heading in the body (case-insensitive, as `has_before_merge` reads it), or any fault from A1's `checkPullRequests` (merged, closed, draft, a failed check) refuses with exit 2. A pending check is polled every `APPROVAL_QUEUE_POLL_S` seconds (default 30) up to `APPROVAL_QUEUE_POLL_MAX_S` (default 900), then refuses, as old lines 199 and 451 to 461 do. Then `gh pr merge <n> --repo <repo> --merge --match-head-commit <head>`, and on success `recordMerged(root, {repo, number, sentence, at})`, which writes the line under `<store>/merged/` where A3's front page reads it through `listMerged`. A `gh` failure prints gh's error and exits 1. The draft refusal is new (the old `land` let `gh` refuse it). `--round` isn't ported: the design's command table gives `land` two arguments.
9. **`restart` adds a trial before the swap.** It ports old lines 478 to 630 in TypeScript, with these changes:
