### Task 3. `approval-queue restart`

- Outcome: a new subcommand that takes no argument. Anything else prints the usage and exits 2. It is dispatched with the early forms, before the retired-forms `case` at line 387, and exits there. It computes the port, the state root, and the app directory with the expressions at lines 438, 16, and 461. Stdout stays empty. Build output goes to `server.log`.
  1. One at a time. It takes `<state root>/restart.lock` with a non-blocking `flock`. When another `restart` holds it, this one says so on stderr and exits 1 having touched nothing.
  2. Stage. It removes any leftover `approval-queue/.stage` and copies the app's source there: everything but `node_modules`, `build`, `.svelte-kit`, `.stage`, and the two `.prev` directories. It runs `npm ci` and `APPROVAL_QUEUE_PORT=<port> npm run build` inside the stage. The running server and its `build` are untouched. If either command fails, `restart` names the log on stderr and exits 1 with nothing swapped.
  3. Lock. It opens `<state root>/start.lock` on descriptor 9 and takes `flock 9`, the lock and descriptor `queue_item` uses at lines 720 to 721. It holds the lock until the new server answers or the rollback ends.
  4. Repair. A `build.prev` or `node_modules.prev` left by a killed run is settled first. It moves back when its live directory is missing, and is removed when the live directory exists.
  5. Find. The old server is the process `ss` shows listening on `127.0.0.1:<port>`.
     - `restart` goes on only when that process's command line is exactly `node <app>/build` and its environment holds this state root in `APPROVAL_QUEUE_STATE`.
     - Any other listener, or one `ss` shows without a process id, makes it exit 1 with nothing stopped and nothing swapped.
     - It skips the stop only when `ss` shows no listener and `curl -sf <base>/` fails, the test line 722 uses. No listener with an answering `/` is exit 1 with nothing touched.
  6. Stop. It sends the old process SIGTERM and waits up to 10 seconds until the port has no listener and `curl` fails. From this signal until step 7 or step 8 ends, `restart` ignores TERM, HUP, and INT. A port still held after 10 seconds is exit 1 with nothing swapped. The stderr line names the process it signalled and says whether `/` still answers.
  7. Swap and start. `build` becomes `build.prev` and the staged build becomes `build`. `node_modules` becomes `node_modules.prev` and the staged one takes its place. Every rename uses `mv -T`, and a directory that is absent is skipped. It starts the server with the environment and command line of line 729, with both lock descriptors closed for the child. It waits up to 10 seconds for `/` to answer. Success needs all of these: a listener under a process id different from the old one, whose command line is `node <app>/build`, and a 200 from the page of one undecided item when the state root holds one.

  9. Clean up. On success it removes both `.prev` directories, prints `approval-queue: restarted, pid <n>` on stderr, and exits 0. The stage is removed on every exit, and on a signal that arrives before step 6.

## Stops and standing answers

| What happens | Answer |
| --- | --- |
| Auto mode refuses a command | Use the answer under "Refused commands". Where that says a refusal is a stop, or names no alternative, the pass parks (approved standing answer 2). |
| An acceptance item can't be met as written, or a mechanism row proves false | The pass parks under approved standing answer 12. Write the stop under `## Stop` in `docs/STATUS.md`. |
| `npm ci` fails inside the test because the cache is cold | Run `npm ci --prefix approval-queue` in the worktree, then the test once more. A second failure with the same cause is a stop. |
| The test finds another process on its port, or no port from 7931 to 7999 is free | Run the test once more: it picks its port at random. If no port is free, record the `ss -ltn` output in the PR and stop. |
| A test server outlives a failed test run | Leave it running and name its process id and port in the PR's `## Decisions`. It serves a removed temporary tree and never the live queue. |
| A task passes twice its estimate | One line in `## Decisions` with both numbers. The run goes on. |
| The run's path passes 120 minutes | The run goes on. Rule 9 parks a plan before code is written and sets no stop after it. The PR's `## Planning misses` gets one `[estimate]` line with the actual path. |
| The review ends on `escalate`, or a second read is short of `accept` | A stop, as executor rule 5 says. |
| A fix would need `vite.config.ts`, a dependency, or a file outside the lists above | Allowed when it serves an acceptance item, and recorded in `## Planning misses` with the `[file-list]` tag. A change to what an acceptance item says is a stop. |
