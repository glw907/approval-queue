## What the pass changes

Today the repo holds the old app in `approval-queue/` and the 1,124-line bash command. Nothing in it parses a document as the round design defines one, and the mockup that specifies the new pages lives only in the initiatives record.

After this pass the repo has a new project in `next/`. It holds a document library that parses and renders a document and lists its faults, a comparison of two versions of a document, a file store under `~/.local/state/approval-queue/store/`, and a command whose one subcommand is `check`. `node next/cli check <doc.md>` prints each fault with its line and exits 1, or exits 0. The mockup is copied into `docs/mockup/`, its documents cleaned of change marks and mockup-only header keys. The gate type-checks and tests `next/` beside the old app.

Nothing the old queue does changes. Nothing reads the new store yet: A2's command and A3's pages are its first users. The live server is never rebuilt or restarted in this pass, and the executor never runs the installed `approval-queue`.

Out of scope: `send`, `collect`, `withdraw`, and every other subcommand (A2); every route, component, and stylesheet (A3); `src/app.css`; Playwright; the meaning of a decision record beyond its two required keys (A4); notes threads (A5); `README.md`, `BACKLOG.md`, and `docs/STATUS.md`, which only A6 edits, apart from a stop under `## Stop`.

### Task 3. The comparison and the store (pair with task 2)

- Outcome, the comparison, in `next/src/lib/doc/compare.ts`, which imports nothing from task 2's files:
  1. Drop each version's header. The header is never compared.
  2. Split each body into blocks: runs of non-blank lines separated by blank lines, where a list item line (`- `, `* `, or a number, a period, and a space) and a `:::` line also start a block, and the title line is a block of its own. A block's leading Markdown marker (`# `, `- `, `1. `) is not part of its compared text. Each block keeps its first line number in its version.
  3. Match blocks by exact text with a longest-common-subsequence pass. Between two matched blocks, pair the removed and added blocks by position, the first removed with the first added. A block left over is a whole-block removal or addition.
  4. In a paired block, split the text into clauses at `,`, `.`, `;`, `:`, `?`, and `!`, each mark its own token, and match the tokens with a longest-common-subsequence pass. When the two share no clause but punctuation, the whole block is one change. A shared run of punctuation alone between two changes joins them into one.
  5. Each change gives a passage: its removed text and added text, as exact substrings of the two versions, and its line in the returned version, the line where the change starts. Spaces at either end of a changed run count as shared, so a passage's removed and added texts each start and end on a non-space character, unless one is empty. Without this rule the third passage comes out with a leading space on both sides, where the hand marks keep the space outside.
  6. When no block and no clause is shared, `whole` is true and the passages are empty.
  7. `marked` is the returned source with `{--removed--}{++added++}` placed at each passage.
